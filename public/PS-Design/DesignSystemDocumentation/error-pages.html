Error Pages

404, 400, 401 and generic error screens.

Overview

Figma: 404, 400, 401, Error (Generic)Code: only the 401 container

Error pages tell the user what happened and give one clear way out. Figma defines four: 404, 400, 401 and a generic error. In code only .AccessDenied-container / .AccessDenied (in css/common/_common.scss) exist; the old sample pages 404.html and AccessDenied.html are marked deprecated, so build new pages from this page.

Writing guidelines

  • Say what happened in plain words, then what the user can do. No codes or stack traces on screen.
  • One primary action («Back to home»); add «Details» only for 404 when helpful.
  • Use the same illustration style across all codes.

Accessibility

  • The page title and the main heading must say the error (for example «404 · Page not found»).
  • Return the real HTTP status code, not only a friendly page.
  • Decorative illustrations use alt="".

RTL notes

  • The back arrow inside the button is rotated 180° in the existing styles so it points toward the reading start in RTL; check it when you reuse the markup in LTR.
  • Text is centered, so the layout is the same in both directions.

Do & Don't

Do

  • Use the status that matches the problem (404 missing, 401 sign-in, 400 bad request).
  • Always offer a way out: Home or Back.

Don't

  • Do not show technical details or stack traces to users.
  • Do not blame the user.
