Table

Data table with settings bar, header, rows with tags or actions, loading / empty states and pagination.

المكوّن: الجدول الملفات: _table.scss آخر تحديث: 25 أكتوبر 2026

Purpose & when to use

The data table lists records (requests, cases, users) with a settings bar, column headers, rows with actions or status tags, and pagination. Code: css/components/_table.scss on top of Bootstrap .table. Figma: moi-table (page ❖ Components / Table).

  • Use it for any list of more than a few records that the user scans, filters or acts on.
  • For one record’s details use Cards with entity fields, not a one-row table.

Usage rules

Do

  • Keep column order the same across pages; put the record reference first (start side).
  • Show statuses and priorities with the Tag component and its approved colours.
  • Over 8 columns: offer «تخصيص» (column chooser) and keep the most important columns visible.
  • Keep cell text short (one line); long values go to the details page or a tooltip.

Don’t

  • Don’t put edit / delete in tables of read-only records.
  • Don’t hide the settings bar or pagination when the table is empty.
  • Don’t use Bootstrap’s generic .badge or .btn-outline-* inside the table.

Accessibility & RTL

  • Use real <th> for headers; add scope="col".
  • Icon-only action buttons need aria-label (and a tooltip for sighted users).
  • Mark the current page with aria-current="page" and disabled arrows with aria-disabled="true".
  • RTL: the first column is on the right; numbers and dates stay LTR inside cells.
