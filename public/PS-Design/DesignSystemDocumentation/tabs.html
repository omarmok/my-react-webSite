Components / Tabs

Tabs

Tabs display several content sections in the same space, showing one section at a time. The project has two separate patterns, both layered on top of Bootstrap's native tabs (.nav-tabs / .tab-content).

المكوّن: التبويبات الملفات: _nav.scss, _tabs.scss آخر تحديث: 25 أكتوبر 2026

Purpose & when to use

Standard Bootstrap tabs (.nav-tabs + .tab-content) for a bordered card-style tab panel with text/table content — they take the design-system look directly, with no extra class. Mobile has its own tab bar (.moi-mobile-tab) at the end of the page.

Anatomy

Bootstrap tabs (design-system look)

A bordered tab panel with a light background. Use Bootstrap's native nav and .tab-content as they are: the system styles them directly, so the .tabsDesign class is not needed (it stays only as a legacy alias). The markup is the same as in the Bootstrap 5.0 docs (components/navs-tabs).

Element Class Description
Root nav:has(> .nav-tabs) No root wrapper needed; .tabsDesign is a legacy alias.
Tab bar nav > .nav-tabs The tab bar itself, with a light background.
Content panel .tab-content Tab content container, with a border and rounded corners.
Active pane .tab-content > .active The currently visible pane; displayed as flex with a white background and soft shadow.

Usage rules

  • Use standard Bootstrap tab behavior (data-bs-toggle="tab") to switch panes; neither pattern has its own custom JavaScript behavior.

Accessibility Guidance

  • Follow standard Bootstrap/ARIA tab markup: role="tablist" on the nav, role="tab" on each link, role="tabpanel" on each pane, and aria-selected for the active state.

Mobile tabs

This bar is for mobile (the mobile app). It is the mobile-tab component in Figma, built from mobile-tab-atoms: icon + label + count, with the active item on a light green background and an underline. Web uses .nav-tabs and .tabsDesign above.

RTL notes

  • Tabs start from the right in RTL and the active indicator follows.
  • Arrow keys move in the visual direction: Right goes to the previous tab in RTL.

Do & Don't

Do

  • Use tabs for sibling views of the same data.
  • Keep tab labels short and unique.

Don't

  • Do not use tabs for steps in a flow; use the stepper.
  • Do not hide required content in a non-default tab.
