Text Inputs & Selects

This page documents the current field implementation from SCSS through .form-control, .form-select, .form-content, and the implemented validation, readonly, and disabled states.

المكوّن: حقول النص والقوائم الإصدار: 2.0 — حالات كود المنصات آخر تحديث: 28 أكتوبر 2026

Overview

The current field API is built on .form-control and .form-select, with real supporting patterns such as .form-content, .input-group-text, and .input-with-icon. Validation is applied through .is-invalid/.is-err, .is-valid/.is-ok, or .was-validated.

.form-control uses a 44px default height and the Platforms Code «Text Input» states: Gray-400 border, a black underline on focus and a grey fill while pressed.
.form-select shares the current DS font/padding rules and supports data-size.
The current implementation does not expose an API named .input-wrapper or .select-field.

Usage rules

  • Always start from .form-control or .form-select instead of inventing a new field wrapper.
  • Use .form-content with a position-relative wrapper when a leading image/icon is required inside the field.
  • data-size="sm|md|lg|xl" controls input and select size. When omitted, .form-control keeps its current base size.
  • Use .is-invalid/.is-err and .is-valid/.is-ok, or rely on native form validation via .was-validated.
  • Distinguish readonly from disabled: readonly stays focusable/copyable, while disabled is unavailable for interaction.
  • Use .input-with-icon and .input-with-icon-time only for the date/time background icon pattern that already exists in CSS.

Anatomy

A field is composed of a label, an input/select control, and helper or error text. When a leading icon is needed, .form-content is used inside a relative wrapper.

  • Label: Use a matching <label for> and field id.
  • Control: .form-control for text entry and .form-select for native selects.
  • Leading icon: Place an image/icon inside .form-content within a position-relative wrapper.
  • Attached affordance: Use .input-group-text when a prefix or suffix is required.
  • Messaging: Use .form-text or .invalid-feedback with aria-describedby.

Do & Don't

Do

  • Tie helper and error text through aria-describedby and keep a matching label.
  • Use .input-group-text for paired prefixes/suffixes instead of custom floating affordances.
  • Keep decorative inner icons aria-hidden="true" and let text carry the primary meaning.

Don't

  • Do not use .input-wrapper, .has-leading, or .select-field; they are not part of the current API.
  • Do not document the select as a custom button/listbox when the real implementation is native .form-select.
  • Do not blur readonly and disabled, and do not stack conflicting validation states on the same field.

Accessibility

The current field patterns rely on native controls, so labels and semantic linking should be preserved instead of replaced with unnecessary custom layers.

  • Tie every label to a unique matching id.
  • Use aria-describedby for helper, error, or supporting text.
  • Set aria-invalid="true" whenever an error state is shown.
  • The focus indicator is the 2px black underline (high contrast on white); never hide it or add outline: none without a replacement.
  • The default Gray-400 border (the Platforms Code choice) is 2.5:1 on white, so always keep a visible label above the field and do not rely on the border alone to identify it.
  • The underline animation switches off with prefers-reduced-motion.
  • Treat leading images/icons inside .form-content as decorative via aria-hidden="true" or alt="".
  • Keep the native semantics of <select> instead of documenting a custom role="listbox" pattern.
  • Verify RTL and the approved project font after language switching because the controls depend on logical padding and inherited typography.

Edge cases

  • textarea.form-control starts at a 150px default height, and with data-size it becomes auto-height with a size-based minimum.
  • When .input-group-text sits next to .form-control[data-size], the add-on follows the current field font size.
  • Do not use readonly with .form-select; the current readonly treatment applies to text controls only.
  • In Arabic and English, verify the background-icon alignment of .input-with-icon and .input-with-icon-time with both short and long values.
  • If you use .was-validated, do not stack an opposing manual valid/error class on the same field.

Developer API

The snippet below summarizes the classes and attributes that exist in the current implementation.

<div class="form-text text-muted" id="identity-help">نص مساعد</div>

<div class="input-group">
  <input class="form-control" type="text" data-size="lg" />
  <span class="input-group-text">.gov.sa</span>
</div>

<input class="form-control is-invalid" type="text" aria-invalid="true" />
<input class="form-control is-valid" type="text" />
<input class="form-control is-warning" type="text" />
<textarea class="form-control" aria-describedby="notes-help"></textarea>

<select class="form-select" data-size="lg">
  <option selected>اختر الجهة الأمنية</option>
</select>
  • The current public names are .form-control, .form-select, .form-content, .input-group-text, .input-with-icon, and .input-with-icon-time.
  • Manual validation uses .is-invalid/.is-err and .is-valid/.is-ok, and native forms also support .was-validated.
  • New: .is-warning for the warning state; pressed and focus work automatically through :active and :focus with no extra class.
  • The current page should not rely on .input-wrapper, .has-leading, .select-trigger, or .select-menu.
