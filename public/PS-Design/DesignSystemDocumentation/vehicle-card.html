Vehicle Card

A vehicle summary on the Person Card shell.

Component: Vehicle CardFiles: _PersonCardInfra.scssLast updated: November 2, 2026

Overview

Figma: moi-vehicle-cardCode: reuses the Person Card shell

The vehicle card summarizes one vehicle. It is built on the same shell as the Person Card (.moi-person-card), with vehicle fields instead of person fields, so no new class is needed.

Component objective

  • Show a vehicle at a glance in inquiry results and case records: plate, make, model, year, status and the key registration data.
  • Give the next actions on the same card (vehicle record, insurance status, print).
  • Keep one visual language with the Person Card so an officer reads both the same way.

Usage

  • Use it for a single vehicle with its status. For a list of vehicles use the Table.
  • The header shows identity (image, status, plate, make, model, year); the body shows the secondary fields; an alert shows warnings such as «wanted».
  • Do not create a separate vehicle layout: reuse the Person Card shell and change only the fields.

Design guidelines

  • Order of identity fields: plate, make, model, year. Everything else goes in the details body.
  • One status tag in the header; use the tag colors of the system (Tags).
  • A warning (wanted, stolen) always appears in the notification line, in text, not only in color.

Accessibility

  • Plate numbers mix Arabic and Latin letters: wrap them in <bdi> so the order is not scrambled in RTL.
  • Icon-only buttons need aria-label («طباعة»).
  • The vehicle photo needs a meaningful alt.

RTL notes

  • The shell is built for dir="rtl"; the image sits at the start side and the details flow right to left.
  • Plate and chassis values stay left-to-right inside <bdi>.

Acceptance criteria

  • Uses only .moi-person-card classes, Tags and Buttons; no new class or hard-coded color.
  • Plate and chassis wrapped in <bdi>; status is text; buttons labelled.

Do & Don't

Do

  • Build it on the Person Card shell so related cards look alike.
  • Keep plate number and owner in the same positions on every screen.

Don't

  • Do not invent new card classes for vehicles.
  • Do not show plate numbers in a different direction than the rest of the data.
